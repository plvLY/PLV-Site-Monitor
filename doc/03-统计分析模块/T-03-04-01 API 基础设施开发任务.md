# PLV Site Monitor — T-03-04-01 API 基础设施开发任务

## 一、任务目标

基于现有 PLV Site Monitor 项目，完成统计分析 API 的公共基础设施。

本次只开发公共模块，不实现具体统计 SQL 和统计业务接口。

## 二、开发前检查

1. 检查现有项目目录和文件。
2. 检查 Netlify Functions、Drizzle、数据库连接方式。
3. 检查现有 Collection API 的响应格式和异常处理。
4. 检查现有 Vitest 配置和测试规范。
5. 不覆盖或破坏现有实现。
6. 优先复用已有代码，避免重复封装。

## 三、需要实现的模块

建议目录：

```
netlify/functions/_shared/analytics/
├── response.ts
├── errors.ts
├── query-validator.ts
├── date-range.ts
├── pagination.ts
└── authorization.ts
```

### 1. response.ts

统一成功响应：

```
{
  "success": true,
  "data": {},
  "meta": {}
}
```

统一错误响应：

```
{
  "success": false,
  "error": {
    "code": "INVALID_QUERY",
    "message": "Invalid query parameters."
  }
}
```

要求：

- 正确设置 JSON Content-Type。
- 支持 HTTP 状态码。
- 不向客户端暴露数据库连接信息和内部异常堆栈。

### 2. errors.ts

统一错误类型及错误码：

- INVALID_QUERY
- INVALID_DATE_RANGE
- INVALID_TIMEZONE
- UNAUTHORIZED
- SITE_ACCESS_DENIED
- SITE_NOT_FOUND
- INTERNAL_ERROR

要求：

- 统一错误类型。
- 统一错误码和 HTTP 状态映射。
- 未知异常统一转换为 INTERNAL_ERROR。

### 3. query-validator.ts

实现通用查询参数校验。

要求：

- 解析 URLSearchParams。
- 必须拒绝重复的关键参数，避免参数歧义。
- 支持 required、可选参数。
- 非法参数统一返回 INVALID_QUERY。

### 4. date-range.ts

支持：

- today
- yesterday
- 7d
- 30d
- custom

规则：

- 默认 range = 7d。
- custom 必须同时提供 start 和 end。
- start、end 必须是合法日期。
- 必须满足 start < end。
- 时间范围统一采用 [start, end)。
- 时区从站点配置获取。
- 验证 IANA 时区。
- 正确处理夏令时 DST。
- 不使用固定 24 小时计算本地自然日。
- 明确区分本地日期边界和 UTC 时间戳。

注意：自定义时间范围最大跨度及其小时/日粒度规则，按已验收的 T-03-02 API 设计处理，不自行修改。

### 5. pagination.ts

统一分页：

| 参数      | 默认值 | 限制   |
| --------- | ------ | ------ |
| page      | 1      | >= 1   |
| page_size | 10     | 1～100 |

计算：

```
offset = (page - 1) * pageSize;
```

统一返回：

```
{
  "page": 1,
  "page_size": 10,
  "total": 25,
  "total_pages": 3
}
```

无数据时 total 和 total_pages 均为 0。

### 6. authorization.ts

建立统一认证与站点授权边界。

重要要求：

- 当前项目尚未完成用户认证体系。
- 不要虚构 JWT、用户身份或权限数据。
- 不要把 site_id 当作认证凭据。
- 不要把 Origin 校验当作用户认证。
- 定义明确的认证上下文和站点授权接口。
- 尚未接入认证提供者时，默认拒绝受保护的 Analytics 请求。
- 允许通过测试注入 Mock 身份和授权实现。
- 后续可以接入统一用户认证模块，而不需要修改统计业务代码。

## 四、测试要求

为每个模块编写 Vitest 单元测试。

重点覆盖：

1. 成功响应和错误响应结构。
2. 未知异常处理。
3. 重复查询参数。
4. 非法日期。
5. custom 缺少 start 或 end。
6. start >= end。
7. 非法时区。
8. DST 春季和秋季边界。
9. 默认分页 1/10。
10. 最大分页 100。
11. page 小于 1。
12. page_size 小于 1 或大于 100。
13. total_pages 计算。
14. 未认证拒绝访问。
15. 无权访问 site_id 时拒绝访问。
16. 授权成功场景使用 Mock 验证。

## 五、禁止事项

- 不添加未经确认的认证机制。
- 不改变已经验收的统计指标定义。

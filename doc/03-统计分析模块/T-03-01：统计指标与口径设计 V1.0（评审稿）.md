# T-03-01：统计指标与口径设计 V1.0（评审稿）

- 项目：PLV Site Monitor
- 模块：Analytics Module
- 阶段：T-03-01
- 状态：待评审
- 设计原则：统计口径统一、可验证、可扩展，优先使用现有采集数据，不提前引入尚未实现的事件能力。

## 1. 设计目标

建立统一的统计指标定义，为后续统计查询 API、聚合查询、管理后台图表提供数据标准。

首版重点回答：

- 一个页面被访问多少次？
- 有多少独立访客？
- 产生了多少次访问会话？
- 有多少访问只浏览了一个页面？
- 哪些页面最受欢迎？

## 2. 数据来源

首版统计基于现有 `page_events` 表。

| 字段                           | 用途               |
| ------------------------------ | ------------------ |
| site_id                        | 站点隔离           |
| event_id                       | 事件唯一标识       |
| event_type                     | 事件类型           |
| visitor_id                     | 独立访客识别       |
| session_id                     | 会话识别           |
| page_url                       | 完整页面地址       |
| page_path                      | 页面路径统计       |
| received_at                    | 服务端接收时间     |
| occurred_at                    | 客户端事件发生时间 |
| country_code                   | 国家 / 地区        |
| region                         | 区域               |
| city                           | 城市               |
| browser / os                   | 浏览器和操作系统   |
| utm_source / medium / campaign | 营销来源           |

注意：原始 IP 清理不会删除事件记录，因此不影响 PV、UV、Session 等基础统计。

## 3. 核心指标定义

### 3.1 PV（Page Views）

**定义：** 指定时间范围内，成功采集的 `page_view` 事件总数。

计算规则：

```
PV = COUNT(page_view events)
```

规则：

- 仅统计 `event_type = page_view`。
- 同一个访客重复访问同一页面，每次均计入 PV。
- 同一页面刷新，产生新的有效事件时计入 PV。
- 重复提交相同 `site_id + event_id` 不重复计数。
- 按 `site_id` 隔离。

### 3.2 UV（Unique Visitors）

**定义：** 指定时间范围内，访问过该站点的独立访客数量。

计算规则：

```
UV = COUNT(DISTINCT visitor_id)
```

规则：

- 只统计有效的 `page_view` 事件。
- 同一个 visitor_id 在多个页面访问，只计为一个 UV。
- 同一个 visitor_id 在多个会话访问，在统计范围内仍只计一个 UV。
- 不使用 IP 或 IP Hash 计算 UV。
- 按 `site_id` 隔离。

注意：清理原始 IP 不影响 UV，因为 UV 使用 visitor_id。

### 3.3 Sessions（访问会话数）

**定义：** 指定时间范围内发生过页面访问的独立会话数量。

计算规则：

```
Sessions = COUNT(DISTINCT session_id)
```

规则：

- 只统计有效的 `page_view` 事件。
- 同一会话访问多个页面，只计一个 Session。
- 同一访客产生多个 session_id，分别计数。
- 按 `site_id` 隔离。

当前 SDK 使用 sessionStorage 保存 session_id，因此首版会话识别以 SDK 生成的 session_id 为准，不额外通过 IP 或 UA 推断会话。

### 3.4 Bounce Rate（跳出率）

**定义：** 指定时间范围内，仅产生一次页面浏览事件的会话占全部会话的比例。

首版计算规则：

```
跳出会话数 = 仅包含 1 条 page_view 事件的 session_id 数量

Bounce Rate = 跳出会话数 / Sessions × 100%
```

规则：

- 以 session_id 为统计单位。
- 同一会话产生 1 条 page_view，计为跳出。
- 同一会话产生 2 条或以上 page_view，不计为跳出。
- 当 Sessions 为 0 时，Bounce Rate 返回 null，不返回 0%。
- 仅根据当前已采集的 page_view 判断，不推断用户是否真正离开网站。

限制：首版没有点击、转化、交互等事件，因此该指标属于基于页面浏览次数的简化跳出率，不等同于具备完整互动事件定义的分析平台跳出率。

### 3.5 Page Performance（页面访问分布）

首版展示页面维度的访问情况。

| 指标          | 计算方式                                 |
| ------------- | ---------------------------------------- |
| Page PV       | 该 page_path 的 page_view 数量           |
| Page UV       | 该 page_path 下 distinct visitor_id 数量 |
| Page Sessions | 该 page_path 下 distinct session_id 数量 |
| PV Share      | 页面 PV / 全站 PV × 100%                 |

规则：

- 按 `site_id + page_path` 分组。
- 默认按 Page PV 降序排列。
- PV 为 0 时，PV Share 返回 null 或不展示。
- 不将 URL query 参数作为页面路径维度。

## 4. 时间范围与时间口径

首版建议支持：

| 时间范围     | 说明           |
| ------------ | -------------- |
| Today        | 当日           |
| Yesterday    | 昨日           |
| Last 7 Days  | 最近 7 天      |
| Last 30 Days | 最近 30 天     |
| Custom Range | 自定义日期范围 |

时间筛选规则：

- 首版建议以服务端 `received_at` 作为统计时间字段。
- 使用左闭右开区间：`[start, end)`。
- 所有时间边界必须明确时区。
- 不直接信任客户端设备时间作为统计时间依据。

选择 received_at 的原因：服务端时间更稳定，避免客户端时钟偏差、错误时区或人为修改设备时间影响统计结果。

## 5. 统计维度

首版预留以下统计维度：

| 维度         | 数据字段     | 首版用途     |
| ------------ | ------------ | ------------ |
| 页面         | page_path    | 页面访问排行 |
| 国家         | country_code | 地域统计     |
| 区域         | region       | 地域细分     |
| 城市         | city         | 城市分布     |
| 浏览器       | browser      | 浏览器分布   |
| 操作系统     | os           | 系统分布     |
| 来源         | referrer     | 来源分析     |
| UTM Source   | utm_source   | 营销来源     |
| UTM Medium   | utm_medium   | 营销媒介     |
| UTM Campaign | utm_campaign | 营销活动     |

以上维度中，实际能否展示取决于采集数据是否存在。缺失数据应归入 Unknown 或单独展示，不得虚构数据。

## 6. 统计准确性与边界规则

1. 所有统计查询必须包含 `site_id` 条件。
2. 不同站点之间不得混合统计。
3. 统计只读取有效的 `page_view` 事件。
4. 数据库唯一约束 `(site_id, event_id)` 保证重复事件不重复计数。
5. UV 使用 visitor_id，不使用 IP。
6. Sessions 使用 session_id，不使用 IP。
7. 原始 IP 清理后，历史事件仍参与基础统计。
8. 没有数据时，数量指标返回 0；比例指标在分母为 0 时返回 null。
9. 统计查询必须明确时间范围及其时区。
10. 首版不主动过滤机器人流量，统计结果应标注为未经 Bot 过滤的采集数据。

## 7. 首版不纳入的指标

以下指标暂不进入 T-03-01 首版：

- 转化率
- 用户留存率
- 用户路径 / 漏斗
- 平均停留时长
- 实时在线人数
- 点击热力图
- 自定义事件分析
- Bot 流量识别与过滤

原因：当前采集模块以 PageView 为核心，部分指标需要额外事件、时间戳或用户行为数据支持。

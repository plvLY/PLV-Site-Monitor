# T-02-01-04 数据采集接口设计

**版本：** V1.2
**状态：** 最终验收版

## 1. 接口目标

Tracker 与 Netlify Functions 之间采用 HTTP API 通信。

MVP 核心接口：

```
POST /api/collect
OPTIONS /api/collect
```

## 2. 请求格式

```
POST /api/collect
Content-Type: application/json
Origin: https://example.com
```

请求体：

```
{
  "siteId": "SITE_UUID",
  "eventId": "EVENT_UUID",
  "eventType": "page_view",
  "visitorId": "VISITOR_UUID",
  "sessionId": "SESSION_UUID",
  "page": {
    "url": "https://example.com/products",
    "path": "/products",
    "title": "Products"
  },
  "referrer": "https://google.com/",
  "utm": {
    "source": "google",
    "medium": "organic",
    "campaign": null,
    "term": null,
    "content": null
  },
  "occurredAt": "2026-11-05T10:00:00.000Z"
}
```

## 3. 服务端字段

以下字段由服务端生成或读取：

- ip_address
- country_code
- region
- city
- user_agent
- received_at
- referrer_host

不允许客户端自报值覆盖服务端信息。

客户端提交的 IP、IP Hash 或地域字段均不作为数据采集依据。

服务端不生成或保存 `ip_hash`，不实现 HMAC IP Hash。

## 4. 成功响应

HTTP 202：

```
{
  "success": true,
  "data": {
    "accepted": true,
    "eventId": "EVENT_UUID"
  }
}
```

## 5. 重复事件

HTTP 200：

```
{
  "success": true,
  "data": {
    "accepted": false,
    "duplicate": true,
    "eventId": "EVENT_UUID"
  }
}
```

## 6. 错误响应

### 参数错误：400

```
{
  "success": false,
  "error": {
    "code": "INVALID_REQUEST",
    "message": "Invalid request payload"
  }
}
```

### 站点不存在或停用：404

```
{
  "success": false,
  "error": {
    "code": "SITE_NOT_FOUND",
    "message": "Site is unavailable"
  }
}
```

### 域名不允许：403

```
{
  "success": false,
  "error": {
    "code": "DOMAIN_NOT_ALLOWED",
    "message": "Origin is not allowed"
  }
}
```

### 请求超限：429

```
{
  "success": false,
  "error": {
    "code": "RATE_LIMITED",
    "message": "Too many requests"
  }
}
```

### 服务端异常：500

```
{
  "success": false,
  "error": {
    "code": "INTERNAL_ERROR",
    "message": "Unable to process event"
  }
}
```

不得向客户端返回数据库连接信息、SQL 和内部堆栈。

## 7. 服务端处理流程

```
flowchart TD
    A[收到 POST] --> B[解析 Origin]
    B --> C[读取 Site ID]
    C --> D[检查站点状态]
    D --> E[检查域名绑定]
    E --> F[校验请求体]
    F --> G[限流及请求大小限制]
    G --> H[获取 Netlify Context IP/Geo]
    H --> I[解析 User-Agent]
    I --> J[生成 received_at]
    J --> K[事件去重]
    K --> L[写入数据库]
    L --> M[返回响应]
```

## 8. 域名和 CORS

允许的 Origin 必须匹配站点绑定的域名。

- 精确匹配。
- 不使用任意 Origin 反射。
- 不使用 `Access-Control-Allow-Origin: *` 作为默认策略。
- 不开启 credentials。
- OPTIONS 必须正确处理。
- 返回动态 Origin 时设置 `Vary: Origin`。

CORS 不是认证机制，不能阻止非浏览器客户端伪造请求。

## 9. 请求校验

| 字段       | 规则               |
| ---------- | ------------------ |
| siteId     | UUID               |
| eventId    | UUID               |
| visitorId  | UUID               |
| sessionId  | UUID               |
| eventType  | MVP 仅 page_view   |
| page.url   | 合法 URL，限制长度 |
| page.path  | 限制长度           |
| page.title | 最大 500 字符      |
| occurredAt | 合法时间           |
| UTM        | 只允许指定字段     |
| 请求体     | 最大 16 KB         |

客户端不得通过请求体提供或覆盖以下服务端数据：

- IP 地址
- 国家代码
- 行政区
- 城市
- User-Agent 对应的设备、浏览器和操作系统解析结果
- 服务端接收时间

## 10. IP 和地域

从 Netlify Function Context 获取：

```
export default async (req: Request, context: Context) => {
  const ip = context.ip;
  const geo = context.geo;

  // 使用服务端请求上下文处理事件
};
```

不得使用客户端 JSON 的 IP 或地域字段。

本地开发环境可能使用模拟 IP 和地域，真实验证必须在部署环境进行。

IP 数据策略：

- 只使用服务端 Context 获取原始 IP。
- 原始 IP 存储在 `page_events.ip_address`。
- 原始 IP 最长保留 30 天。
- 到期后由定时清理任务将 `ip_address` 置为 `NULL`。
- 清理依据为服务端 `received_at`。
- 清理不删除历史事件，也不影响其他事件字段。
- UV 使用 `visitor_id`，Session 使用 `session_id`，不依赖 IP 或 IP Hash。
- 不保存 `ip_hash`，不实现 HMAC IP Hash。

## 11. 限流和防刷

需要具备：

- 单 IP 限流。
- 单 Site ID 限流。
- 请求体大小限制。
- 异常请求频率检测。
- 站点停用后拒绝采集。

正式环境限流需要共享存储或平台能力，不能仅依赖单个 Function 实例的内存 Map。

## 12. 验收标准

1. 合法站点可以上报。
2. 一个站点的多个绑定域名均可上报。
3. 未绑定域名拒绝上报。
4. 已停用站点拒绝上报。
5. 客户端不能伪造 IP 和地域。
6. 重复事件不会重复入库。
7. 非法参数被拒绝。
8. 请求体超限被拒绝。
9. CORS 预检正常。
10. 数据库异常返回统一错误。
11. 原始 IP 最长保留 30 天。
12. IP 到期清理不删除历史事件。
13. UV 和 Session 分别使用 visitor_id、session_id 统计。
14. 不保存 ip_hash，不实现 HMAC IP Hash。

**结论：该接口协议作为 T-02-03 Function 实现基线。**
